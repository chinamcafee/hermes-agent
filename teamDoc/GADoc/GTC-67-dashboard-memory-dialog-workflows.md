# GTC-67 Dashboard 记忆治理弹窗化操作流

日期：2026-05-24

## 背景

GTC-66 已补齐团队记忆库的列表、来源标签、管理员创建、编辑、停用和硬删除能力，但第一版页面把创建、编辑和审核表单同时堆在“记忆治理”Tab 内。该信息架构会让管理员在浏览团队记忆库时被多个无关表单打断，也不符合 Dashboard V2 “列表优先、操作下钻”的设计原则。

本次改造只调整 Dashboard 交互形态，不改变后端 API 契约。

## 功能范围

- “记忆治理”Tab 首屏只展示状态筛选、加载按钮、新建按钮、统计卡片、团队记忆库列表和待审队列。
- 创建团队记忆从常驻表单改为“创建团队记忆”弹窗。
- 编辑团队记忆从常驻表单改为列表行“编辑”触发的“编辑团队记忆”弹窗。
- 审核待审记忆从常驻表单改为待审队列行“审核”触发的“审核团队记忆”弹窗。
- 停用和彻底删除保留为团队记忆列表行级动作。

## UX 约束

- Tab 一级页面不展示 `记忆内容`、`Memory ID`、`Review ID` 等操作表单字段。
- 弹窗使用 `role="dialog"` 和 `aria-modal="true"`，并提供明确关闭按钮。
- 页面默认信息架构以列表、来源标签、状态和行级动作组织；表单只在执行具体动作时出现。
- 移动端下弹窗和工具栏纵向排列，避免按钮和字段挤压。
